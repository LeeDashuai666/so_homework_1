# WSL perf 与 CPU 拓扑验证

此目录针对教师建议验证实验基础设施，不修改 BOLT 优化实现或宿主机配置。

```bash
cd stage_1
source ./env.sh
python3 experiments/wsl-perf-check/run.py --output results/wsl-perf-check-rerun
```

输出目录必须是新目录。默认串行运行，固定一个来宾逻辑 CPU，使用 7 次重复；保留原始 perf CSV、标准输出、反汇编、拓扑、全部命令与 JSON 摘要。依赖 GCC、objdump、taskset、Python 标准库和 perf。通过环境变量 `PERF_BIN` 或 `--perf` 指定可执行文件。

在观察结果前约定以下检查：

1. 真正的 C hello world 及睡眠对照能成功计数。单次 hello world 的动态加载和 I/O 占比较高，不据此证明计数精度。
2. 固定汇编循环每轮为 3 条指令和 1 条条件分支；另一个循环每轮多 8 条 NOP。检查 N、2N、4N 的增量斜率，指令与分支误差分别不超过 1%，并检查 NOP 增量 8N。固定代码下计数重复变异系数不超过 1%。
3. 相同汇编分支循环每轮执行 2 条条件分支，固定模式与伪随机模式只改变输入。伪随机分支失误率至少比固定模式高 5 个百分点。
4. 四个硬件事件成组采集，所有计数有效且计数器实际运行时间至少占 99%，避免用被大量 multiplex 缩放的数值作解释。双倍工作量的 cycles 比值应在 [1.5, 2.5]，只作合理性检查。
5. 睡眠 500ms 时线程 CPU 时间少于 25ms、用户态 cycles 少于长计算对照的 5%，避免把墙钟等待误当执行。
6. 检查同一循环在不同来宾核心上的计数一致性；另在来宾报告的 sibling 与其他核心上分别启动一个可终止的干扰进程，检查被测进程的指令数不因其他进程而显著膨胀（1% 范围）。这些对照不用于推断真实宿主 SMT 的收益或损失。

脚本另外尝试 `perf record -e cycles:u` 采样定位已知热点，单独记录支持情况，不把某个 `perf stat` 检查通过扩大为 LBR、cache 事件、采样调用栈或原生 Linux 等价精度的保证。cycles、耗时和干扰敏感度如实报告，不要求重复 cycles 完全相同。

首轮使用 16 KiB 周期序列，伪随机模式失误率只有约 0.69%，未通过原定 5 个百分点的分支对照门槛。该轮 140 次原始记录全部保留。当前版本改用 1 MiB 序列，重新执行相同门槛的全部检查；这是针对输入是否足够难预测的后续实验，没有降低或重写首轮验收标准。

SMT sibling/core ID 来自 WSL 的虚拟拓扑。`taskset` 固定来宾 vCPU，不能据此声称已经独占一个宿主物理核心或其两个 SMT 线程。实验不关闭 SMT、不修改 `.wslconfig`、不下线 CPU、不调整频率。
